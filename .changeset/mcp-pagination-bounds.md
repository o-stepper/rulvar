Bound the MCP tools/list pagination itself (RV1602). The eighteenth comparison benchmark called out the gap the RV1515 bounds left open: a server answering unique cursors over empty pages grows neither the tool count (`maxTools` never trips) nor any timeout (each page answers inside `listMs`), so the sweep could spin wire calls forever. Two guards close it. The cursor-echo cycle guard is unconditional: a page whose `nextCursor` equals the cursor it was queried with makes no pagination progress and is never a legitimate step, so the sweep refuses with a typed `ConfigError` on the second page at the latest. The new opt-in `maxPages` (positive integer, validated with the other bounds) caps the sweep's wire call count for the general no-progress case; like `maxTools` it fails closed, refusing a server that still reports another page past the cap rather than silently importing a subset of its declared surface. Absent config preserves previous behavior except the cycle refusal, which only ever fires on a protocol-violating server.
