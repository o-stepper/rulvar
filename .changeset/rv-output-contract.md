The unified output contract (the v1.71 experiment review, P0.1/P0.2/P0.3/P1.1): `finishContract(manifest)` generates the prompt statement, the stock validator set, a stable sha256 hash, and golden self-test fixtures from ONE immutable manifest, so the prompt a model follows and the validators a host enforces cannot drift apart by construction. `finishValidation.contract` wires it into orchestrate: the construction-time golden self test fails a stale validator as a ConfigError BEFORE any provider call (the experiment burned a full paid run on three renamed section headings), the contract statement is injected into the coordination and synthesis prompts, every contract validator must be present in the configured set by name, and the run journals a frozen bundle descriptor (`orchestrator_finish_validation_bundle`) with supersession on resume under a fixed contract. `preflightEstimate` accepts the same declaration and reports drift as the error finding `output-contract-validator-mismatch` with a `finishValidation` echo block. Two new stock validators: `wordCountValidator` (formal length bounds as code) and `sectionCitationsValidator` (per-section citation coverage, because a total count hides sections with zero provenance). Absent contract and selfTest, every existing configuration keeps byte-identical prompts, journals, and reports.
